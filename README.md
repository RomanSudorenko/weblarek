# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Абстрактный базовый класс для всех компонентов интерфейса.

Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

В приложении используются две основные сущности: товар и покупатель. Также используются типы, описывающие данные для обмена с сервером.

### Основные типы данных

#### Тип TPayment

Тип описывает доступные способы оплаты заказа.

```ts
type TPayment = 'card' | 'cash' | '';
```

Значения типа:

- `'card'` — оплата картой;
- `'cash'` — оплата наличными;
- `''` — способ оплаты ещё не выбран.

#### Интерфейс IProduct

Интерфейс описывает товар интернет-магазина.

```ts
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

Поля интерфейса:

- `id: string` — уникальный идентификатор товара.
- `description: string` — описание товара.
- `image: string` — путь к изображению товара.
- `title: string` — название товара.
- `category: string` — категория товара.
- `price: number | null` — стоимость товара. Значение `null` используется для товаров, которые нельзя приобрести.

#### Интерфейс IBuyer

Интерфейс описывает данные покупателя, необходимые для оформления заказа.

```ts
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

Поля интерфейса:

- `payment: TPayment` — выбранный способ оплаты.
- `email: string` — адрес электронной почты покупателя.
- `phone: string` — номер телефона покупателя.
- `address: string` — адрес доставки.

### Типы обмена с сервером

#### Тип ApiPostMethods

Описывает методы запроса, используемые в интерфейсе `IApi`.

```ts
type ApiPostMethods = 'POST' | 'PUT' | 'DELETE';
```

#### Интерфейс IApi

Описывает объект для выполнения запросов, который передаётся в конструктор `ShopApi`.

```ts
interface IApi {
    get<T extends object>(uri: string): Promise<T>;
    post<T extends object>(
        uri: string,
        data: object,
        method?: ApiPostMethods
    ): Promise<T>;
}
```

- `get` — принимает адрес запроса и возвращает промис с данными ответа.
- `post` — принимает адрес, отправляемые данные и необязательный метод запроса. Возвращает промис с данными ответа.
- `T` — тип данных ответа сервера.

#### Интерфейс IProductsResponse

Интерфейс описывает объект, получаемый от сервера при запросе каталога товаров.

```ts
interface IProductsResponse {
  total: number;
  items: IProduct[];
}
```

Поля интерфейса:

- `total: number` — количество товаров, полученных с сервера.
- `items: IProduct[]` — массив товаров.

#### Тип TOrder

Тип описывает данные, которые передаются на сервер при оформлении заказа.

```ts
type TOrder = IBuyer & {
  total: number;
  items: string[];
};
```

Тип включает все поля интерфейса `IBuyer`, а также:

- `total: number` — итоговая стоимость заказа.
- `items: string[]` — массив идентификаторов товаров, выбранных покупателем.

#### Интерфейс IOrderResponse

Интерфейс описывает объект, получаемый от сервера после успешного оформления заказа.

```ts
interface IOrderResponse {
  id: string;
  total: number;
}
```

Поля интерфейса:

- `id: string` — идентификатор оформленного заказа.
- `total: number` — итоговая стоимость оформленного заказа.

## Модели данных

### Класс ProductCatalog

Хранит каталог товаров и товар, выбранный для просмотра.

Конструктор:

`constructor(events: IEvents)` — принимает брокер событий приложения.

Поля класса:

- `products: IProduct[]` — массив товаров каталога.
- `selectedProduct: IProduct | null` — выбранный товар, если товар не выбран, содержит `null`.
- `private readonly events: IEvents` — брокер, через который модель сообщает об изменении данных.

Методы класса:

- `setProducts(products: IProduct[]): void` — сохраняет массив товаров и генерирует событие `products:changed`.
- `setSelectedProduct(product: IProduct): void` — сохраняет выбранный товар и генерирует событие `product:selected`.
- `getProducts(): IProduct[]` — возвращает массив всех товаров каталога.
- `getProductById(id: string): IProduct | undefined` — возвращает товар по идентификатору или `undefined`, если товар не найден.
- `getSelectedProduct(): IProduct | null` — возвращает товар, выбранный для подробного отображения.

### Класс Basket

Класс отвечает за хранение и изменение списка товаров, которые покупатель добавил в корзину.

Конструктор:

`constructor(events: IEvents)` — принимает брокер событий приложения.

Поля класса:

- `items: IProduct[]` — массив товаров, добавленных покупателем в корзину.
- `private readonly events: IEvents` — брокер, через который модель сообщает об изменении данных.

Методы класса:

- `getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине.
- `addItem(product: IProduct): void` — добавляет товар в корзину и генерирует событие `basket:changed`.
- `removeItem(product: IProduct): void` — удаляет товар по его идентификатору и генерирует событие `basket:changed`.
- `clear(): void` — очищает корзину и генерирует событие `basket:changed`.
- `getTotal(): number` — возвращает общую стоимость товаров, находящихся в корзине.
- `getCount(): number` — возвращает количество товаров в корзине.
- `hasItem(id: string): boolean` — принимает идентификатор товара и возвращает `true`, если товар находится в корзине, иначе возвращает `false`.

### Класс Buyer

Класс отвечает за хранение, изменение и проверку данных покупателя, необходимых для оформления заказа.

Конструктор:

`constructor(events: IEvents)` — принимает брокер событий приложения.

Поля класса:

- `payment: TPayment` — выбранный способ оплаты.
- `address: string` — адрес доставки.
- `phone: string` — номер телефона покупателя.
- `email: string` — адрес электронной почты покупателя.
- `private readonly events: IEvents` — брокер, через который модель сообщает об изменении данных.

Методы класса:

- `setData(data: Partial<IBuyer>): void` — обновляет переданные поля, не изменяя остальные. Значения `undefined` пропускаются. После обновления генерирует одно событие `buyer:changed`.
- `getData(): IBuyer` — возвращает все сохранённые данные покупателя.
- `clear(): void` — очищает все поля покупателя и генерирует событие `buyer:changed`.
- `validate(): Partial<Record<keyof IBuyer, string>>` — проверяет поля на пустые строки и возвращает ошибки. Если ошибки в поле нет, соответствующее свойство отсутствует. Данные модели этот метод не изменяет.

## Слой коммуникации

### Класс ShopApi

Класс отвечает за взаимодействие приложения с сервером.

Использует композицию: получает объект с интерфейсом `IApi` в конструкторе и выполняет через него запросы.

Конструктор:

`constructor(api: IApi)` — принимает объект, реализующий интерфейс `IApi` и предоставляющий методы для выполнения запросов к серверу.

Поля класса:

- `api: IApi` — объект, используемый для взаимодействия с сервером.

Методы класса:

- `getProducts(): Promise<IProductsResponse>` — выполняет GET-запрос на эндпоинт `/product/` и возвращает объект, содержащий массив товаров.
- `createOrder(order: TOrder): Promise<IOrderResponse>` — принимает данные заказа, выполняет POST-запрос на эндпоинт `/order/` и возвращает объект с результатом успешного оформления заказа.

## Слой представлений View

Классы слоя представления отвечают за отображение данных и обработку действий пользователя.

Компоненты View не работают напрямую с моделями данных и API. Данные для отображения передаются им Презентером. О действиях, затрагивающих другие компоненты или модели, View сообщает через переданные обработчики. 

DOM-элементы находятся в конструкторах и сохраняются в полях. Слушатели событий устанавливаются один раз при создании компонента.

Все компоненты наследуют поле `container` и метод `render(data?: Partial<T>): HTMLElement` от `Component`. Без аргументов `render()` возвращает корневой элемент компонента. Сеттеры изменяют отображение и не возвращают значение.

Карточки `CatalogCard`, `PreviewCard` и `BasketCard` наследуют сеттеры `title` и `price` от `Card`. Формы `OrderForm` и `ContactsForm` наследуют сеттеры `valid`, `errors` и обработку отправки от `Form`.

### Типы данных слоя View

Для компонентов представления используются отдельные типы, описывающие данные, необходимые для отображения.

#### Тип TCard

Базовый тип данных карточки товара.

```ts
type TCard = Pick<IProduct, 'title' | 'price'>;
```

Содержит:

- `title: string` — название товара.
- `price: number | null` — цена товара.

#### Тип TCatalogCard

Тип данных карточки товара в каталоге.

```ts
type TCatalogCard = Pick<
    IProduct,
    'title' | 'price' | 'image' | 'category'
>;
```

Содержит:

- `title: string` — название товара.
- `price: number | null` — цена товара.
- `image: string` — изображение товара.
- `category: string` — категория товара.

#### Тип TPreviewCard

Тип данных карточки подробного просмотра товара.

```ts
type TPreviewCard = Pick<
    IProduct,
    'title' | 'price' | 'image' | 'category' | 'description'
> & {
    buttonText: string;
    buttonDisabled: boolean;
};
```

Дополнительно содержит:

- `buttonText: string` — текст кнопки действия с товаром.
- `buttonDisabled: boolean` — состояние активности кнопки.

#### Тип TBasketCard

Тип данных карточки товара в корзине.

```ts
type TBasketCard = TCard & {
    index: number;
};
```

Дополнительно содержит:

- `index: number` — порядковый номер товара в корзине.

#### Тип TBasketView

Тип данных компонента корзины.

```ts
type TBasketView = {
    items: HTMLElement[];
    total: number;
    buttonDisabled: boolean;
};
```

Поля:

- `items: HTMLElement[]` — массив карточек товаров.
- `total: number` — итоговая стоимость корзины.
- `buttonDisabled: boolean` — состояние кнопки оформления заказа.

#### Тип THeader

Тип данных компонента шапки страницы.

```ts
type THeader = {
    counter: number;
};
```

Поля:

- `counter: number` — количество товаров в корзине.

#### Тип TGallery

Тип данных компонента каталога.

```ts
type TGallery = {
    items: HTMLElement[];
};
```

Поля:

- `items: HTMLElement[]` — массив карточек товаров каталога.

#### Тип TModal

Тип данных модального окна.

```ts
type TModal = {
    content: HTMLElement;
};
```

Поля:

- `content: HTMLElement` — содержимое модального окна.

#### Тип TForm

Базовый тип данных формы.

```ts
type TForm = {
    valid: boolean;
    errors: string;
};
```

Поля:

- `valid: boolean` — состояние валидности формы.
- `errors: string` — текст ошибки.

#### Тип TOrderForm

Тип данных первого шага оформления заказа.

```ts
type TOrderForm = TForm & Pick<IBuyer, 'payment' | 'address'>;
```

Дополнительно содержит:

- `payment: TPayment` — выбранный способ оплаты.
- `address: string` — адрес доставки.

#### Тип TContactsForm

Тип данных второго шага оформления заказа.

```ts
type TContactsForm = TForm & Pick<IBuyer, 'email' | 'phone'>;
```

Дополнительно содержит:

- `email: string` — электронная почта покупателя.
- `phone: string` — номер телефона покупателя.

#### Тип TSuccess

Тип данных компонента успешного оформления заказа.

```ts
type TSuccess = {
    total: number;
};
```

Поля:

- `total: number` — итоговая сумма заказа.

### Card<T>

Базовый компонент карточки товара.

Содержит общую для всех видов карточек работу с названием и ценой товара.
Параметр типа ограничен как `T extends TCard`.

Наследуется от: `Component<T>`

Конструктор:

`constructor(container: HTMLElement)` — принимает корневой элемент карточки.

Поля класса:

- `titleElement: HTMLElement` — элемент для отображения названия товара.
- `priceElement: HTMLElement` — элемент для отображения цены товара.

Сеттеры:

- `set title(value: string)` — устанавливает название товара.
- `set price(value: number | null)` — отображает цену в формате `750 синапсов`. При значении `null` выводит «Бесценно».

### CatalogCard

Компонент карточки товара в каталоге.

Наследуется от: `Card<TCatalogCard>`

Конструктор:

`constructor(container: HTMLElement, onClick: () => void)`

Параметры конструктора:

- `container: HTMLElement` — корневой элемент карточки.
- `onClick: () => void` — обработчик выбора товара.

Поля класса:

- `imageElement: HTMLImageElement` — изображение товара.
- `categoryElement: HTMLElement` — категория товара.

Сеттеры:

- `set image(value: string)` — устанавливает переданный адрес изображения через унаследованный метод `setImage()`.
- `set category(value: string)` — устанавливает категорию товара и соответствующий CSS-класс.

При клике по карточке вызывается обработчик `onClick`.

Компонент подробного просмотра товара.

## События приложения

Взаимодействие между слоями приложения реализовано с использованием брокера событий `EventEmitter`.

Модели данных генерируют события при изменении хранимых данных. Компоненты представления сообщают о действиях пользователя через обработчики, переданные им при создании. Обработчики генерируют соответствующие события через `EventEmitter`.

Презентер подписывается на события и связывает между собой модели данных и компоненты представления.

### События моделей данных

- `products:changed` — изменился каталог товаров.

  Генерируется моделью `ProductCatalog` после сохранения массива товаров.

- `product:selected` — изменился товар, выбранный для подробного просмотра.

  Генерируется моделью `ProductCatalog` после изменения выбранного товара.

- `basket:changed` — изменилось содержимое корзины.

  Генерируется моделью `Basket` после добавления товара, удаления товара или полной очистки корзины.

- `buyer:changed` — изменились данные покупателя.

  Генерируется моделью `Buyer` после изменения или очистки данных покупателя.


### Тип TBuyerInput

Тип данных события `buyer:input`. Объявлен в `src/types/index.ts`.

```ts
type TBuyerInput = {
    field: keyof IBuyer;
    value: string;
};
```

- `field` — имя изменённого поля покупателя.
- `value` — новое значение поля.

### События представления

- `card:select` — пользователь выбрал карточку товара в каталоге.

  Данные события:

  - `id: string` — идентификатор выбранного товара.

- `product:toggle` — пользователь нажал кнопку добавления или удаления товара в подробной карточке.

  Данные события:

  - `id: string` — идентификатор товара.

  Презентер определяет по состоянию корзины, необходимо добавить товар или удалить его.

- `basket:remove` — пользователь нажал кнопку удаления товара из корзины.

  Данные события:

  - `id: string` — идентификатор удаляемого товара.

- `basket:open` — пользователь нажал кнопку корзины в шапке страницы.

- `order:start` — пользователь нажал кнопку оформления заказа в корзине.

- `order:next` — пользователь отправил первую форму оформления заказа и переходит к вводу контактных данных.

- `order:submit` — пользователь отправил вторую форму оформления заказа и завершает оформление покупки.

- `buyer:input` — пользователь изменил одно из полей формы оформления заказа.

  Данные события:

  - `field: keyof IBuyer` — имя изменённого поля.
  - `value: string` — новое значение поля.

- `success:close` — пользователь нажал кнопку закрытия сообщения об успешном заказе.

  Событие не передаёт дополнительных данных.

### Принцип обработки событий

Компоненты представления не изменяют данные приложения самостоятельно. Они только сообщают о действиях пользователя.

Модели данных не управляют интерфейсом. После изменения данных они генерируют соответствующее событие.

Презентер обрабатывает события представления, вызывает методы моделей данных, а после получения событий об изменении моделей обновляет необходимые компоненты интерфейса.

Обработчики событий Презентера не вызывают `emit()` напрямую. Для изменения данных они обращаются к моделям, которые отправляют свои события. Обработчики действий View создаются через `events.trigger()` и передаются компонентам.

## Презентер

Презентер находится в файле `src/main.ts`. Он связывает модели данных, компоненты представления и API. Отдельный класс для Презентера не создаётся.

В `main.ts` создаются экземпляры:

- `EventEmitter` — общий брокер событий.
- `Api` и `ShopApi` — классы для работы с сервером.
- `ProductCatalog`, `Basket` и `Buyer` — модели данных.
- Компоненты слоя View.

Товары и данные покупателя хранятся в моделях.

Обработчики действий View создаются через `events.trigger()` и передаются компонентам. Обработчики событий Презентера вызывают методы моделей и компонентов представления.

### Вспомогательные функции Презентера

- `openModal(content: HTMLElement): void` — передаёт содержимое в компонент `Modal` и открывает модальное окно.
- `renderBasket(): HTMLElement` — получает товары из модели, создаёт карточки `BasketCard` и передаёт их в `BasketView` вместе с общей суммой и состоянием кнопки оформления. Нумерация начинается с `1`. Возвращает корневой элемент корзины.
- `renderBuyerForms(): void` — получает данные покупателя и ошибки валидации, обновляет поля и состояние обеих форм. Для первого шага учитываются ошибки `payment` и `address`, для второго — `email` и `phone`.

### Загрузка каталога

После установки обработчиков вызывается `shopApi.getProducts()`. Презентер добавляет `CDN_URL` к полю `image` каждого полученного товара и сохраняет список в `ProductCatalog`. После сохранения модель генерирует `products:changed`.

При ошибке загрузки сообщение выводится в консоль.

### Обработка событий моделей

`products:changed`

Презентер получает товары из `ProductCatalog`, создаёт карточки `CatalogCard` и передаёт их DOM-элементы в `Gallery`. Каждая карточка получает обработчик выбора со своим идентификатором товара.

`product:selected`

Презентер получает выбранный товар и проверяет его наличие в корзине. Для товара без цены устанавливается заблокированная кнопка «Недоступно». Для товара в корзине — «Удалить из корзины», для остальных — «Купить».

Данные передаются в `PreviewCard` через `render()`. Карточка открывается через `openModal()`.

`basket:changed`

Обновляет счётчик товаров в шапке и содержимое корзины через `renderBasket()`.

`buyer:changed`

Презентер вызывает `renderBuyerForms()`. Обновляются значения полей, сообщения об ошибках и состояние кнопок. После очистки модели поля форм тоже очищаются.

### Обработка событий представления

`card:select`

Презентер получает товар по идентификатору и сохраняет его как выбранный. Если товар не найден, обработчик завершает работу.

`product:toggle`

Презентер получает текущий выбранный товар через `ProductCatalog.getSelectedProduct()`. Если товар не выбран или его цена равна `null`, обработчик завершает работу.

Если товар уже находится в корзине, он удаляется. Если товара нет — добавляется.

`basket:remove`

Презентер находит товар по идентификатору и удаляет его через модель `Basket`. Отображение обновляется по последующему событию `basket:changed`.

`basket:open`

Презентер подготавливает содержимое корзины через `renderBasket()` и открывает его в модальном окне.

`order:start`

Если корзина не пустая, Презентер обновляет состояние форм и открывает первый шаг оформления — `OrderForm`.

`buyer:input`

Передаёт изменённое поле и его значение в `Buyer.setData()`.

После сохранения модель генерирует `buyer:changed`, по которому обновляются формы.


`order:next`

Открывает форму контактов через `openModal()`.

`order:submit`

Собирает объект `TOrder` из данных покупателя, суммы корзины и идентификаторов товаров. Перед запросом блокирует кнопку через `contactsForm.setLoading(true)`.

В блоке `try` отправляет заказ через `ShopApi.createOrder()`. После успешного ответа очищает корзину и данные покупателя через методы `clear()`, затем открывает `Success` с суммой `response.total`.

При ошибке запроса товары и данные сохраняются, а в форме контактов появляется сообщение об ошибке.

В блоке `finally` вызывает `contactsForm.setLoading(false)`. Форма восстанавливает доступность кнопки. 

`success:close`

Презентер закрывает модальное окно с сообщением об успешном заказе.

### Общий принцип работы

Компонент View сообщает о действии пользователя. Презентер обрабатывает событие и вызывает нужный метод модели. После изменения данных модель генерирует своё событие, по которому Презентер обновляет отображение.

При открытии модального окна его содержимое также подготавливается из актуальных данных. DOM внутри карточек, корзины и форм изменяют соответствующие компоненты View.
